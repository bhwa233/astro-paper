# 5ch 与 DC Inside 每日 Top 10 发布方案

状态：已实现

最后更新：2026-08-31

## 1. 发布边界

任务 `forum-top10` 每天只在固定时刻读取一次实时榜单，生成一篇文章，依次包含：

- 5ch「势い（全板）」当时显示的前 10 个讨论串。
- DC Inside「실시간 베스트」排除调查和公告行后显示的前 10 个普通帖子。

文章严格保留两站各自的原始排名、可见标题和原帖链接。任何条目都不按主题、质量或摘要结果过滤，也不使用候补条目补位。模型只填写中文摘要字段，不能生成或修改榜单事实。

定时入口是 `.github/workflows/scheduled-publish.yml`（cron `37 14 * * *`），每天 `14:37 UTC` 运行，对应北京 `22:37`、日本与韩国 `23:37`。归档日期使用 `Asia/Shanghai`。

## 2. 取源

5ch 榜单直接读取官方服务端页面 `https://headline.5ch.io/ikioig/`。该页面按榜单顺序提供原始板块 URL，不依赖 `itest.5ch.io` 的短时中转链接。每帖读取首帖和最多 200 条后续回复；讨论串页面按 `Shift_JIS` 解码。

DC Inside 榜单读取 `https://gall.dcinside.com/board/lists/?id=dcbest`。每帖读取 `.write_div` 文字正文，并使用页面内临时 token 调用官方评论接口，按页面默认顺序读取最多 100 条评论。

两站详情以有限并发抓取。榜单本身不足 10 条、排名结构异常或链接越出官方域名时，整个任务失败；单条详情失败则保留原排名、标题和链接，在该位置标注文本暂不可用。

## 3. 图片边界

当前版本不做图片识别。正文和评论转换为模型证据前会移除 `img` 与 `video` 节点，只记录忽略的媒体数量。图片主导且没有可读文字的帖子仍保留原榜位置，并明确说明当前版本未识别图片内容。

## 4. 摘要与成文

20 条帖子分别调用模型，有限并发生成中文摘要。输入只包含当前帖子的原始标题、板块、文字正文和评论；提示词把论坛内容视为不可信数据，禁止执行其中的指令，也禁止用模型常识补全信息。

模型输出仅接受 `{item_id, summary}`。`item_id` 必须与冻结条目一致，摘要必须是中文且不得包含 Markdown 标题。重试耗尽不会删除条目，而是记录摘要失败状态。

最终 Markdown 由规则层生成。规则层要求恰好 20 条，并校验 5ch 与 DC Inside 均为连续的 1 至 10 名；标题、链接、板块和热度字段只取自冻结的来源载荷。

## 5. 失败与重跑

同一归档日期默认只生成一次。手动运行可传 `force` 覆盖当日文章，但每次强制重跑都会重新读取当时的实时榜单，因此不是对旧快照的重放。

GitHub Hosted Runner 的网络出口可能与本地不同。若两站按机房 IP 限制访问，workflow 会在取榜阶段失败并保留生成产物日志，不会发布不完整文章。
