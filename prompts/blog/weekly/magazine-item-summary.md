# 任务

根据一篇《{magazine}》文章的原文标题与完整 EPUB 正文生成中文文章级 JSON。你是本期导读的上游步骤，你的结果会被程序固定使用，后续不会再被改写。

- 刊期归档日期：{date}
- 文章编号：{rank}

# 输入证据

每篇输入包含 `原文标题` 和正文。`原文标题` 是专名、产品名、术语和标题语义的优先依据；仅当其为 `-` 时，才从正文判断标题。

```md
{article_text}
```

# 输出格式

只输出一个合法 JSON 对象，不要输出 Markdown、代码围栏或任何解释。必须严格使用输入文章编号：

```json
{
  "rank": {rank},
  "title_zh": "自然、准确的中文标题",
  "one_sentence_summary": "一句话说明文章讨论什么和结论是什么。",
  "core_point": "明确核心论点、关键因果或分歧。",
  "content_summary": "Markdown 正文：完整交代背景、主要事实、论证过程、结论和必要边界，不复刻正文。"
}
```

- `content_summary` 使用 Markdown 正文格式：可用多个自然段、`-` 或 `1.` 列表、`**加粗**` 与 `>` 引用，用它们让长内容更有条理、可读。
- `content_summary` 禁止使用任何标题语法（`#`、`##`、`###`、`####` 等）；标题层级由后续程序统一控制。
- 其余字段（`title_zh`、`one_sentence_summary`、`core_point`）保持单行纯文本，不要使用 Markdown 结构。

# 术语与命名

- 公司、产品、项目、组织、人名、书刊节目、模型、协议、标准、编程语言、代码库、库名、命令、版本号和缩写，保留输入中的原文拼写、大小写和连字符；不得强行翻译、音译或用中文近义词替换。
- 对具有稳定中文通行译法的通用技术概念，使用规范中文；对无把握或新出现的概念、行业俚语、双关词，保留英文术语或译为清楚的普通中文，禁止临时杜撰貌似正式的中文术语。
- 同一术语在 `title_zh`、`one_sentence_summary`、`core_point`、`content_summary` 中必须保持一致；不得将上位概念和下位概念混淆。
- `title_zh` 必须是自然中文，但可保留解释所必需的英文专名、产品名、模型名、协议名、标准名、缩写或版本号；不得附带整句英文原题。

不限制各字段字数，但内容必须完整、具体，不能用不同说法重复同一段内容。不得编造引语、数字、立场、链接或输入中不存在的事实；不得提及 EPUB、模型或提示词。
